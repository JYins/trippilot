## 3 个最有代表性的 bad case

**① "别走这条路" → 抽到 `别走这条路`（kind=auth，置信度 0.65）**
为什么错：一次性导航指令被记成了稳定禁忌。"别/不要"正则在设计上就无法区分
"这一次别走"和"以后都别"，只能靠 0.65 全场最低置信度 + Memory Gate 人工确认兜底。
这是预期内的代价，不是 bug——但探针证明它在口语里**高频触发**（4/5 探针误抽）。

**② "我喜欢今天的歌单" → 抽到 `我喜欢今天的歌单`（kind=other，置信度 0.75）**
为什么错：当下一时情绪被记成了稳定偏好。"我喜欢"正则只看句式，
不检查有没有持久性标记（"以后都"/"记住"）。情绪 vs 偏好，规则层面无解，
是 LLM 抽取或多轮上下文该干的活。

**③ "他让我记住明天开会" → 抽到 `明天开会`（kind=other，置信度 0.90）**
为什么错：转述第三人称指令被当成了用户自己的记忆指令。
"记住"正则不看主语是"我"还是"他"。extract.py 注释里预判过
"误抽只可能来自复述，口语第一人称里极少见"——探针证明这个 case 真实存在，
虽然低频，但 0.90 高置信误抽比 0.65 更危险（更容易被 Gate 直接放行）。

## 诚实结论

- fixture 上的 P=R=1.000 是真实但乐观的数字：评测集只有 16 条，
  且断言和实现是同一批人写的（测试即文档）。真实世界 P/R 一定更低。
- 4 类误抽（别/不要一次性指令、我喜欢当下情绪、玩笑称呼、复述记住）**全部是
  extract.py 注释里预先写下的风险点**——代码是诚实的，探针只是把它们复现了。
  设计取舍"宁可误抽、不漏记"成立，但代价是 Gate 的确认压力：
  别/不要型在探针里 precision 只有 0.20。
- 安全底线没破：误抽候选全部经 Memory Gate 才能写盘，没有静默写盘；
  PII 敏感分级兜底（内容关键词）在探针里一次没漏。

**简历能讲的一句**：16 条评测集上记忆抽取 precision/recall 均为 1.00；
另用 12 条对抗探针定位 4 类误抽模式，其中"别/不要"规则在一次性指令探针上
precision 仅 0.20，全部误抽经 Memory Gate 确认兜底、未发生静默写盘。
