## 背景

现有 demo 已能从同一次 `/turn` 响应展示回答和 trace，但 15 个场景横向排列，移动端需要滚动；轨迹只列实际经过的节点，也不容易一眼看出安全链路跳过了什么。页面还需要支持静态托管在 Vercel、后端单独放在 HF Spaces 的部署方式。约束是不改后端契约、不引入依赖、不伪造结果，并保留模拟车况和录制数据的诚实说明。

## 候选方案

1. 保留纵向事件时间线，只调整颜色和间距：改动小，但面试官仍要逐条读，无法快速比较走过、跳过和拦截状态。
2. 固定展示主链路与辅助节点 chip，用 `visited_nodes`、`policy_decisions`、`verification` 和 trace 拼中文摘要：链路更易扫读，代价是跳过状态属于前端推断，且跳过节点没有事件内容。
3. 引入前端框架和可视化库：交互组件更丰富，但违反零依赖和“最小控制台”的仓库约定。
4. Vercel 同时部署页面和 FastAPI：只有一个域名，但当前仓库的 Python 服务不适合按本次静态配置运行，也会扩大部署范围。

## 选择

选择方案 2。主链路按 `intent → clarify → planner → policy_gate → tool_executor → verifier` 固定展示，辅助节点单独展示；节点点击后只呈现由现有结构化字段整理的中文摘要。场景按能力分组并保留全部原文，每个场景增加稳定 id。新增 `?scenario=` 触发真实 `/turn` 请求，新增 `?api=` 指向独立后端。Vercel 只发布 `web/` 静态目录。

## 为什么

固定 chip 让安全链路的完整形态始终可见：`visited_nodes` 出现的节点标成走过，没出现的标成跳过；`policy_decisions` 含 `deny` 时把 `policy_gate` 标成拦截。这个判断简单、确定，也与 graph 只记录实际经过节点的语义一致。代价是前端无法知道一个未经过节点为何被跳过，且没有事件数据可展示，所以详情只诚实说明“本轮未经过”，不补造输入输出。重复经过的恢复链路会合并到同一个节点详情中，阅读更简洁，但不再按次数画多枚 chip。

deep-link 只把既有场景 id 映射回按钮原文，再发起真实 fetch；它不会缓存或伪造响应。`api` 默认同源，只有显式传参时才切换后端，代价是跨域部署时仍需后端正确配置 CORS。页面不再声称四类工具“尚未接入”——媒体、车控、限号、知识问答都有演示实现，只是媒体与车控只改纯软件模拟的座舱状态、限号与知识问答只用录制数据，不连接真实车辆、播放器或实时服务；场景说明如实写清这层边界。“未执行工具调用”只在某轮确实没有工具调用时出现，展示的是后端真实结果，不代指缺失能力。视觉上使用系统字体、中性浅底和单一深绿强调色，放弃渐变和额外图形资源，以换取加载简单和信息层级稳定。

## 对 eval 的影响

本次不修改 `eval/`、fixtures 或后端接口，现有轨迹判分和 15 条场景文案不变。chip 状态只消费已有 `visited_nodes` 与策略结果；deep-link 和可配置 API base 都是前端参数，不改变 eval 输入。回归检查继续使用全量 pytest；静态部署还需人工检查 Vercel 页面能否通过 `?api=` 连接已部署后端。
