## 背景

审查 blocker #5、#6 指出两个相连的漏口：Memory Gate 完全相信调用方给的
`sensitivity`，而抽取层又只靠少量关键词和手机号兜底。因此调用方把
“北京市朝阳区阜通东大街6号”标成 `normal`，或让抽取规则自动产生这个标签，
都能无确认写盘。安全边界必须自己看内容，不能把调用方标签当成安全证明。

## 候选方案

1. 继续扩充 `extract.py` 的关键词，再要求所有调用方正确传标签；改动小，但直接调用
   `remember()` 仍能绕开抽取层，门禁不闭合。
2. 在 Memory Gate 里调用统一的确定性 PII 分类函数，抽取层也复用它；会误拦一些像
   证件号或详细地址的普通文本，但所有写入入口得到同一套保护。
3. 用 LLM 或第三方实体识别模型分类；覆盖面可能更广，但结果不稳定、离线不可用，
   也违反安全判定必须是纯程序的约束。

## 选择

选择方案 2。新增 `memory/pii.py`，只用正则和少量明确关键词识别精确地址、楼栋房间、
身份证、护照、银行卡、手机号和车牌。Gate 将“调用方主动标 sensitive”与“内容分类
命中”取并集：主动升级仍有效，传 `normal` 不能降级 Gate 的判断。

## 为什么

这次先覆盖审查中能实际绕过的国内常见格式。地址模式要求“省/市 + 区/县 +
路/街/道 + 门牌号”，另加“大厦/小区 + 楼/单元/室”，是为了拦住足以定位个人的
内容，同时不把“我喜欢去北京”这种城市偏好全部升级。证件和账号使用长度、边界与
字符集约束，手机号沿用大陆 11 位格式；这些规则不是完整的全球 PII 识别器。

我们明确接受误拦代价：相似的长数字、示例证件号、公司大厦房间也可能进入确认流程。
确认只多一次交互，而漏放会把敏感内容直接落盘，所以这里选择保守。没有尝试校验身份证
校验位或银行卡 Luhn 值，因为测试号、录音识别错误和带空格号码仍是“疑似 PII”，安全
策略本来就要求疑似项确认，严格校验反而会造成漏放。

## 对 eval 的影响

新增 PII 回归维度：调用方把精确地址标为 `normal` 时仍返回 `needs_confirm` 且不写盘；
不含“我家/住址”的精确地址经抽取后升级为 `sensitive`；身份证号、手机号必须命中；
“我喜欢喝美式”保持 `normal`。现有主动标 sensitive、临时记忆拒绝和普通偏好直写行为
继续作为回归项。
