# 决策：记忆候选从对话自动抽取（规则式）

日期：2026-10-05

## 背景

`memory_candidates` 目前靠外部填充（eval 用例里手写），生产对话里
`memory_capture` 节点经常空转：用户亲口说"记住我家地址"，系统却
什么都不记。约束：① AGENTS.md"确定性优先"，安全判定不许调 LLM；
② 无 key 也要能跑（原型 clone 即跑）；③ 红线：不许绕过 Memory Gate，
sensitive 候选照样挂起走现有 human_confirm。

## 候选方案

1. **规则式抽取**（正则识别中文口语偏好句式：记住/以后都/我喜欢/
   别/叫我/我家住在/电话/生日）。
   代价：语义泛化能力弱，"这家店以后常来"这种换说法就抽不到；
   误抽要靠评测集持续度量和调规则。
2. **LLM 抽取**（把 user_request 丢给模型做信息抽取）。
   代价：非确定性，同一句话两次结果可能不同，违反"确定性优先"；
   无 key 环境直接不可用；抽取质量不可测、不可回归。
3. **维持外部填充**（调用方/上游负责给候选）。
   代价：memory_capture 在生产对话里永远空转，记忆功能名存实亡；
   每新增一个调用方都要重复写抽取逻辑。

## 选择

方案 1：规则式抽取（`trippilot/memory/extract.py`）。

## 为什么

- **确定性可测**：同一输入永远同一输出，误抽率可以用
  `fixtures/memory_extract_cases.jsonl` 评测集量化（当前 16 条），
  规则改坏了测试立刻变红；LLM 方案做不到这点。
- **零 key 可跑**：无网络、无模型、无 key 的环境下照常工作，
  符合原型"clone 即跑"的定位。
- **Gate 依然是唯一的门**：抽取只负责"发现候选"，写盘决策
  （deny / confirm / allow）全部在 `evaluate_memory_candidate`，
  抽取模块不复制 Gate 逻辑。sensitive 候选（家庭住址/电话）
  照样挂起走现有 human_confirm，有反例测试证明没确认不写盘。
- 诚实代价：放弃了 LLM 的语义泛化。规则只能覆盖写死的句式，
  换个说法（"这家店不错以后常来"）就漏抽；禁止句式（"别走高速"）
  和一次性指令无法区分，给了全场最低置信度 0.65，靠人工确认兜底。
  规则表是中文口语先验，换个语种/场景要重写。

## 对 eval 的影响

- 新增评测集 `fixtures/memory_extract_cases.jsonl`：正例（9 种口语
  句式能抽到且 kind/sensitivity/confidence 达标）、反例（查天气/
  导航/废话"记住这个"一条不抽）、空输入。
- 新增置信度排序回归：记住(0.90) > 叫我(0.85) > 以后都(0.80) >
  我喜欢(0.75) > 别/不要(0.65)，顺序写死在测试里，改规则不能
  静默打乱。
- 图级回归：外部没给候选时自动抽取（trace 事件带 extracted 计数）；
  抽到的 sensitive 候选必须走 human_confirm（stop_after_confirm，
  未确认不写盘）；human_confirm 回绕时不重复抽取（`extracted_from`
  标记防重复写盘）。
- 后续可加 eval 断言：含"记住"类请求的轨迹必须出现
  `memory_capture` 事件且 extracted ≥ 1。
