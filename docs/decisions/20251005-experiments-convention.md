# 决策：探索实验进 docs/experiments/（报告+脚本+落盘数据）

日期：2026-10-05

## 背景

用户亲口要求"多去探索和试验，好坏都记录，供简历技术故事用"。
探索实验不是产品代码：结论可能是否定性的（"这个想法不行"），
但需要一个固定位置沉淀，保证可复现、可引用。

## 候选方案

1. 实验报告散落在聊天记录里：零成本，但第二天就找不回来，简历数字无出处。
2. 实验代码和报告都进 `docs/experiments/`，代码放 `eval/` 或 `scripts/`、
   数据落盘 `docs/experiments/data/`：多几步，但报告里的每个数字都能重跑验证。
3. 进 `hidden_files/`：那是 agent 内部工作区，用户要看的简历素材放那里不合适。

## 选择

方案 2。

## 为什么

代价是每次实验要多写一个可运行脚本 + 测试，但换来的是"数字可验证"——
这正是 AGENTS.md §6"简历和面试话术里的数字只能来自真实评测报告"的要求。
报告模板固定五段：做了什么 / 怎么测的 / 数字结果 / 好坏都写 / 诚实结论 +
一句"简历能讲的话"。否定性结论同样保留（好坏都记录是用户原话）。

放弃的东西：探索的随意性。随手试一下不写脚本也可以，但想进简历就必须
有脚本 + 落盘数据 + 测试，否则数字不许引用。

## 对 eval 的影响

- 新增 `eval/judge_agreement.py`（实验 A：judge 一致性）+
  `tests/test_judge_agreement.py`。
- 新增 `eval/extraction_pr.py`（实验 B：记忆抽取 P/R）+
  `tests/test_extraction_pr.py`。
- 两个脚本全程离线；live DeepSeek 分数在报告里明确标 pending，不伪造。
- 不改变现有评测维度和 pass/fail 门：实验只读 fixtures、只写报告。
